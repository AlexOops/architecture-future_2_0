# Roadmap вывода Apache Camel / legacy ESB

## Цель

Постепенно вывести Apache Camel из роли центрального интеграционного слоя и не переносить скрытую бизнес-логику в новый транспортный слой.

## Принцип

API Gateway и Event Bus заменяют только транспортную часть ESB.  
ФЛК, трансформации, retry/DLQ, идемпотентность, оркестрация и бизнес-логика переносятся в отдельные целевые компоненты.

## Этап 0. Инвентаризация

Срок: 0-2 месяца.

Работы:

- собрать список Camel routes;
- определить владельцев маршрутов;
- классифицировать маршруты по типам: sync, async, batch, stream;
- найти маршруты с бизнес-логикой;
- найти маршруты с ФЛК и трансформациями;
- определить критичность маршрутов.

Результат:

- сформирован backlog миграции ESB;
- понятны риски и зависимости.

## Этап 1. Подготовка целевых компонентов

Срок: 2-4 месяца.

Работы:

- подготовить API Gateway;
- подготовить Event Bus;
- определить формат data contracts;
- подготовить domain validators;
- подготовить Anti-Corruption Layer;
- подготовить Legacy Adapter / Strangler Layer.

Результат:

- есть целевые места для переноса ответственности ESB.

## Этап 2. Перенос транспорта и ФЛК

Срок: 4-6 месяцев.

Работы:

- перенести простые sync routes в API Gateway;
- перенести async routes в Event Bus;
- перенести ФЛК в domain validators;
- перенести проверки схем в data contracts;
- настроить DLQ и retry для событий.

Результат:

- ESB перестаёт быть основным транспортным слоем;
- новые интеграции создаются уже не в Camel.

## Этап 3. Перенос трансформаций и бизнес-логики

Срок: 6-9 месяцев.

Работы:

- перенести legacy transformations в Anti-Corruption Layer;
- перенести message mappings в Mapping Services;
- перенести batch transformations в Data Platform Ingestion Pipelines;
- перенести бизнес-логику в доменные сервисы.

Результат:

- ESB перестаёт быть местом скрытой бизнес-логики;
- ответственность распределена по доменам.

## Этап 4. Отключение перенесённых routes

Срок: 9-12 месяцев.

Работы:

- отключить перенесённые Camel routes;
- оставить только временные legacy routes;
- проверить потребителей;
- обновить integration catalog;
- подготовить план полного вывода ESB.

Результат:

- Apache Camel остаётся только как временный legacy adapter или полностью выводится, если зависимости устранены.
